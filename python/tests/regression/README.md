# Regression tests (`-m regression`)

## Chunking regression against the 55a0fc2 snapshot goldens

`test_chunking_regression.py` checks that changed code still chunks exactly as the
code that produced the stage0 results did. The owner approved this on 2026-10-06.

**The goldens.** `/rag/snapshots/regression/v1` is a frozen, read-only directory on
coconut. It was generated by running tag `exp/stage0-55a0fc2` (python/ tree `3f202a1`) on
50 stage0 dev-10 documents. Every span row was proven **byte-equal** to the stage0 run's
own `spans_*.jsonl`: 300 of 300 rows, 2,741 spans. The directory's `README.md`,
`SELECTION.md` and `MANIFEST.json` record the inputs, the environment, the tokenizer
revision, and a sha256 for every file.

**What is compared.** The test runs the **current** code over the same inputs with the
same configs, then compares byte-for-byte:
- `FixedTokenWindowChunker` for the 6 stage0 index arms: `fixed_tok{256,512,1024,2048}_ov0pct`,
  `fixed_tok512` (64-token overlap), and `header512`. It compares `[start_char, end_char,
  ntok]` per chunk, and for `header512` also the header strings.
- `sentence_spans()` over the 50 docs and over `canonical-1`
  (`provenance.CANONICAL_SEGMENTATION_SAMPLE`). The punkt backend is required.

The chunking runs in a subprocess, with `HF_HOME` pointed at the goldens' own offline
copy of the SFR tokenizer (`<dir>/hf`, or `RAGSTACK_REGRESSION_HF_HOME`) and
`HF_HUB_OFFLINE=1`. The whole module takes about 10 s.

**When it runs.** It is **not** deselected by default (unlike `perf`), so a plain
`pytest tests` runs it whenever the goldens exist. It skips when:
- `RAGSTACK_REGRESSION_DIR` (default `/rag/snapshots/regression/v1`) is absent, as in CI
  and on other hosts;
- the tokenizer can't load offline;
- for the sentence tests only, `nltk` isn't importable.

It **fails** when:
- the goldens don't match their `MANIFEST.json` checksums;
- the tokenizer resolves to a different revision than the one the goldens record.

To run only this test, use `-m regression`. To exclude it, use `-m 'not perf and not regression'`.

## On a mismatch

The failure names each arm, each document and the first differing span (golden versus
current), plus the nltk, transformers and tokenizers versions against the manifest.

Then decide which kind of difference it is.
- **A bug.** The code change wasn't meant to move chunk boundaries, token counts or
  sentence offsets. Fix the code. Never edit the goldens to make the test pass.
- **An intended change.** For example, a deliberate chunker fix, which the owner accepts
  even though it breaks comparability with the stage0 results. **Re-baseline into a new
  directory**, `/rag/snapshots/regression/v2`. Record in its README why the output
  changed, the PR, and the owner's decision. Generate it from the new pinned commit with
  `v1/generate.py`. Write a new `MANIFEST.json`, make the directory read-only, and point
  `DEFAULT_DIR` in the test at v2 in the same PR. **v1 is never overwritten**, because it
  is the record of what stage0 ran.

A version difference in the environment (nltk, transformers, tokenizers) is a lead, not
a verdict. Find out whether the code or the environment moved before choosing.
