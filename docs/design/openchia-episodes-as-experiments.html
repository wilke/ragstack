1 · Our experiments are Episodes — including the fixed-N ones

OpenChia's definition: a goal, a repeated unit, a result, a credit rule, a stopping rule, declared capabilities, a fixed place in an approved tree. Its one shipped example stops by saturation, so on 2 October I read "Episode" as "open-ended loop" and filed our fixed-N confirmation stages under CWL. That was too narrow. The method loop has four end kinds — exhausted, yield_stop, incomplete, source_failed — and a pre-registered stage is an Episode whose source is a declared finite list and whose continuation rule never fires: 3,738 pairs × 30 presentations, credit as coverage, end by exhausted. The saturation rule is simply the one continuation function registered so far; the registry exists to take others, and upstream has since added a second credit model (epistemic yield) by exactly that route.

For, while, and where CWL sits — now in upstream's own words

ADR-0003 (Episode workflows are not CWL workflows, Proposed) states the position the 3 October comparison arrived at independently: a CWL workflow is "a graph of deterministic process invocations whose shape is known before execution"; an Episode is "a goal pursued by repeated attempts, where a registered numerical function decides at runtime how long to keep trying." Its four load-bearing differences are the ones we named — a stopping rule under uncertainty, non-compositional credit, attest rather than reproduce, and injection containment in the handoff types. And it names the seam: "Episode as the adaptive outer loop, CWL as the deterministic inner tool execution" — an Episode's unit invoking a CWL tool as a declared capability. Our GoWe jobs are that inner tool. It also concedes, usefully, that the registered-function catalog "is presently a hand-edited tuple literal in episode_builder/planner.py."

2 · What changed upstream between 2 and 4 October, and what it does to the gap list

Correction 1. On 2 October I wrote that OpenChia's Run sandbox "cannot do a literature search" because seccomp.py denies socket/connect. The denial is still there and still correct — but ADR-0002 (Accepted, implemented in #11) adds a second brokered request kind: the worker sends an http_request frame and the host dials out under a per-node, human-approved egress_allowlist. Read-only HTTPS to allowlisted hosts is now a sandbox capability. The motivating case in the ADR is the ragstack asm-next study calling https://www.bv-brc.org/ragstack/asm-next/api/.
Correction 2. I listed "live retrieval from inside the worker" as the large gap. For retrieval through the public gateway it is closed by the same ADR. What the egress rules exclude is exactly what our local plumbing is: plain http://, non-default ports, redirects, responses over 917,504 bytes. So localhost:24040 and mango:8003 are unreachable by design — the first should go through the gateway, the second is a model call and belongs to the model broker's launch configuration, not to HTTP egress.

3 · The precedent: the asm-next configuration study, 30 September

The OpenChia repo carries an exported Duet, reports/duet-export-9ada895f/, that is a complete host record of a ragstack experiment being planned. The human asked to "integrate a rag system … asm-next … episodic … find out the best parameter combination and episode structure," and recorded the goal exactly: "Determine, by measured read-only experiment against the BV-BRC RAGstack asm-next tenant, which retrieval and generation parameter combination and which episodic question-answering structure produce the best answers within each ASM paper collection measured separately … leaving behind a per-collection winning configuration and the per-question evidence justifying it."

What stopped it, and what it taught. The last workflow shadow review returned block on contract alignment (one high finding) and concern on four other lenses — the design was not ready — and the host then failed on EpisodeTree depth bound 3 before that mattered. The restart brief says plainly: "It failed in the old host on a depth-bound bug, not on its content." Its capability note is the honest pre-ADR-0002 state: "execute_code can in principle issue any HTTP request … the operator accepts procedural enforcement." ADR-0002 is the structural answer to that sentence.

6 · What to do, in order

  1. Run the smallest brokered-HTTP test against the dev gateway, adapting 10-http-broker-test-prompt.md: two GETs (/health, /v1/collections) with an X-API-Key credential. This settles gap 5's one open question in an hour and proves the chain Duet → approve → build → Run → broker → typed result on this account.
  2. Plan the next designs in the Duet, not in Markdown: option (c) and the hard pointed set as Architectures, with the asm-next contract's budget, noise-floor, holdout and closure rules carried over. Admission validates topology, capabilities and function selections; approval is the pre-registration freeze. This works today, on the Mac, without any run.
  3. Contribute gap 1 upstream. exhaust_declared_source and a declared-coverage credit are the smallest change with the largest effect: they make every pre-registered fixed-N run a first-class Episode.
  4. Materialize the span-filter Episode first (gap 3 test): deterministic, one input file, one output file, no model, no network. If staging works, labeling is next — it is model-only and already fits the broker.
  5. Decide the host. Verify the systemd executor on coconut's systemd 249, or accept that OpenChia plans and runs on the Mac while coconut serves data through the gateway.
  6. Leave the finished confirmation stages on the pinned harness. Re-materializing a run whose data is complete adds risk and no information; the human read, κ, freeze and unblinding stay on the plan's Track A.
Where the two programs meet. The asm-next study and the chunking study are now two experiment programs against the same deployment, one planned in OpenChia and one in pre-registration documents. They already agree on the hard parts — read-only against production, grading as the human protocol, frozen benchmarks, noise floors, hash-verified closures, untested-never-no-effect. The run plan's roles (Owner, Experimenter, Supervisor, Readers) are OpenChia's gates with the approver required to be a different session. Converging the two on one Architecture format is a documentation task, not a research one.
