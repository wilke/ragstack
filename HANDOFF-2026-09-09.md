## 1. The sixty-second version

The question is how coarse and cheap the production index can be for pointed, evidence-seeking
questions. Overlap is settled (cut it). Chunk size is not: the passage-level confirmation run was
redesigned as revision 3 (reach and containment as separate endpoints, a 16k budget, hybrid
retrieval at the served shape, three retrieval modes), its labeler was fixed (whole-sentence
anchors: hallucinated spans 0.08 → 0.003), and the thing it labels turned out to be diffuse — no
canonical span set exists, but a *graded* per-sentence support map is reliable at 30 readings
and agreed on by five models from three families. Its validity is the human read's to establish.

Two calibration findings then bounded what the run can say: the 80 CDS topics cannot power the
size contrasts (joint power 0.37–0.56), and the pointed population is at its ceiling because
every question carries a rare-entity key — and, measured on 2026-09-08, **corpus size does not
change that**. The lever is query hardness. A hard pointed set is planned (PR #526) and awaits
the owner's go.

Meanwhile the confirmation topics are being labeled under quarantine so that whichever way the
decisions fall, the labels exist. Scout finished on 2026-09-09; Qwen needs ≈ 37 h more.

  label freeze. The guard is in code; do not work around it.
- Every design spec gets an independent Fable review before merge — #499 and #517 both had
  load-bearing errors that green tests did not catch.
- Never stop a service by process-name pattern; stop by recorded pid or verified port (#402).
- Live stores: dev tenant only; scratch servers on ephemeral ports; never `:6333`/`:9200`.
- Endpoint politeness: SFR ≤ 2 in flight per endpoint, `:50052` ≤ 4, mango ≤ 4 (Qwen ≤ 5 now,
  the server admits 4). GPUs 6 and 7 stay free.
- Judge runs through the CLI share the owner's session budget; do not run them concurrently with
  long agent sessions.
